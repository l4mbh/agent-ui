# Resilience contract (R1–R15)

Each rule names the component that enforces it and how it is checked. The checks run on the design system's
`/stress` page **and** on every app page that uses the design system.

### Layout (R1–R12)

| Rule | Problem it prevents                                             | Enforced by                                                                                                                                                                                                                                                             | Checked by                                                                                                                                            |
| ---- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1   | Text in two columns overlaps                                    | Every flex/grid child gets `min-w-0`; columns only through `Columns` / `Stack`; text in a column must choose truncate or clamp                                                                                                                                    | Playwright: no element's `scrollWidth > clientWidth`; no two text boxes intersect                                                                   |
| R2   | Items in one dropdown have different widths                     | `DropdownMenu`, `Select`, `Command` items are `w-full`; menu min width = trigger width, max width bounded; overlong items truncate with a tooltip                                                                                                               | Playwright: all items in one menu have equal width                                                                                                    |
| R3   | Status badges shift in and out with label length                | `StatusBadge` takes a fixed set of states; width = longest label of that set **across all languages**; centred, no wrap; sits in a fixed column                                                                                                                 | Playwright: all badges of one set have equal width in both languages                                                                                  |
| R4   | Text is not truncated                                           | `Text` requires `truncate` \| `clamp={n}` \| `wrap`; truncated text gets a tooltip / `title` with the full string                                                                                                                                             | Playwright: every element whose text is clipped (`scrollWidth > clientWidth` with `overflow:hidden`) has a `title` / tooltip with the full text |
| R5   | Buttons overflow when narrow or when a translation is longer    | Button groups only through `ActionBar`: wraps, primary first, folds secondary actions into `⋯` below a width; button labels never wrap                                                                                                                             | Playwright at 360 px: no overflow, primary visible                                                                                                    |
| R6   | Numbers and times jitter; long e-mails / URLs break the box     | `tabular-nums` for times, dates, counts, right-aligned in tables; e-mail/URL/ids `overflow-wrap:anywhere` or middle-ellipsis                                                                                                                                        | Playwright: no overflow with long strings                                                                                                             |
| R7   | A button or switch changes size on hover, press, focus, loading, disabled, checked | State changes only colour and inset shadow / ring — never font weight, border width or padding. Loading keeps the label (invisible) with a spinner on top, sets `aria-busy`, blocks a second click. Fixed height per size. `Switch` is a fixed 36 × 20 track; only the thumb moves | Playwright: the button's box is pixel-identical in all five states; the switch's box (and its label row) in rest, hover, focus, pressed, checked, disabled, and in light and dark |
| R8   | Waiting without a loading state; content jumps in               | Every data component has a same-size `skeleton`; all API calls go through `useResource` returning `pending / error / empty / data` and components must handle all four; no indicator under 200 ms, shown at least 400 ms; long operations say what they are doing | Playwright with a fake API delayed 2 s and failing: skeleton then error state; CLS = 0                                                                |
| R9   | A modal or sheet overflows the screen                           | Header and footer actions stick; only the body scrolls; max height = viewport minus margin; below 640 px a `Dialog` becomes a full-screen `Sheet`                                                                                                                   | Playwright at 360 × 640 with a long form: footer button visible                                                                                      |
| R10  | Blank areas: loading? nothing? broken?                          | `EmptyState`, `ErrorState` at the same size as the content; errors show a friendly sentence + error code, never the system message                                                                                                                                  | Playwright: empty and error fixtures render the right state                                                                                           |
| R11  | Tables on narrow screens                                        | `DataTable` declares its primary column; below 640 px it renders as stacked cards; no unintended horizontal page scroll                                                                                                                                               | Playwright at 360 px: `document.scrollingElement.scrollWidth ≤ innerWidth`                                                                         |
| R12  | Toasts pile up and cover buttons                                | One toast region; at most 3; identical toasts merge with a count; lifted above a sticky action bar                                                                                                                                                                      | Playwright: fire 5 identical toasts → 1 toast with "+4"                                                                                              |

### Experience (R13–R15)

| Rule | Problem it prevents                                              | Enforced by                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Checked by                                                                                                                                                   |
| ---- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R13  | Lists that make people scroll forever                            | `List` / `DataTable` show N items (5–10 per type) then "Show K more (of total)"; over 20 items: grouping with counts and/or filter chips with counts; over 50: pagination or search; "waiting for you" before "done"; a scroll area is at most one screen tall; no nested scroll areas                                                                                                                                                                                                                                                                | Lint: `List` over N without show-more/grouping/pagination; Playwright with 100 items: page height ≤ 2 screens                                             |
| R14  | People don't know what to do on a screen                         | `PageHeader` requires a title **and** one sentence saying what the page is for / what it is waiting on; **one primary action per screen** (a second `primary` in one view is an error); button labels are verb + result, never "OK"; multi-step flows show `Steps`; every status, empty and error state carries a "next step" sentence, naming who is being waited on; icon-only buttons need a label/tooltip and `aria-label`; destructive confirmations state the consequence and repeat the verb on the button                      | Lint: missing description, two primaries, unlabelled `IconButton`; screenshots reviewed with "would a first-time user know what to click?"                 |
| R15  | Something opens and cannot be closed — or closes and loses work | `Dialog`, `Sheet`, `Popover`, `DropdownMenu`, `Select`, `Command`, `Tooltip`, `Toast`, inline expanders: close by **×** (labelled), **Esc**, **click outside**, and **Back** (Dialog/Sheet push a history entry). Unsaved form: any close asks "Discard changes?" first. While submitting: cannot close. On close focus returns to the trigger; on open focus moves in and is trapped. "Show more" always has "Show less". Info toasts auto-dismiss at 5 s with ×; error toasts stay. No modal on top of a modal | Playwright per overlay: open → close by each of the four ways → closed and focus on trigger; type in a form → click outside → prompt shown and text kept |

A new rule = a new case on `/stress` + a new check. A red check blocks a release.
